## 1. Project overview

HazeGuard AI — mobile-first web app: "Understand the air. Plan smarter. Breathe better." Air-quality checks around you, an interactive haze map, AI activity planning, and an AI assistant (BreatheBuddy) that cites real tool output. Built for a student hackathon with free-tier services and honest labelling of demo/estimate data.

## 2. Objectives and requirements

See `AGENTS.md` (stack, security, conventions) and the project brief. Summary: check local air quality with source/unit/timestamp; explore an interactive map; AI activity recommendations; AI Q&A; accounts + preferences; mobile-first with desktop layout; free services; real data where available with demo data clearly labelled; maintainable code.

## 7. Database design

**Implemented (T1B.6 — `database/schema.sql`).** All tables InnoDB / utf8mb4, timestamps stored in UTC, parameterised queries only.

- `users` — id, username UNIQUE, email UNIQUE, password_hash, email_verified_at NULL, status ENUM('pending','active','suspended') DEFAULT 'pending', created_at, updated_at.
- `email_verification_tokens` — id, user_id FK→users (CASCADE), token_hash CHAR(64) UNIQUE, expires_at, used_at, created_at. **Provisioned per brief §9.5 but not yet wired**: the Stage 1A UI verifies email with a 6-digit code (see `email_otps`), so the link-based flow is deferred.
- `email_otps` — id, user_id FK→users (CASCADE), **purpose ENUM('verify_email','login','reset_password')**, otp_hash CHAR(64), expires_at, used_at, attempt_count, created_at. *`purpose` is an addition to §9.5 so one table serves all three code flows.* `reset_password` was added on 2026-10-12 when password reset moved off emailed links.
- `rate_limits` — bucket VARCHAR(191) PK, hits, window_start. *Addition to §9.5*: fixed-window counters for OTP requests and login attempts.

**Dropped 2026-10-12 — `password_reset_tokens`.** Password reset originally emailed a link built from `APP_URL`, and this table held the hashed link tokens. The `APP_URL` coupling was the defect: a stale value made every link point at a dead port, and a `localhost` link cannot be opened from a phone. Reset now issues a 6-digit code on `email_otps` like the other two flows, so the table has no reader left and was dropped (`database/migrations/2026-10-12-reset-uses-otp.php`) along with `TokenModel::issueResetToken()/consumeResetToken()` and `Mailer::sendPasswordReset()`.

Indexes on token_hash / user_id / expires_at as applicable; FKs to `users`. Later stages add `activity_plans`, `user_preferences`, `saved_locations`, optional `alert_rules`.

**Dev/prod difference:** local dev runs XAMPP's **MariaDB 10.4.32**; production targets MySQL 8. The schema uses only features common to both (InnoDB, utf8mb4, ENUM, `IF()` in upserts, no MySQL-8-only syntax).
